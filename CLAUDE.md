# CLAUDE.md — 01_Dashboard_English (Emma English Studio)

A **family** English learning dashboard: a parent teaches and gives extra practice to their own children (about 3–10 years old) at home.
Local-first web app on the family's Windows PC. Content comes **from the family's own textbooks** (image-based PDFs in `resources/book/`).
A second, **online build** of the same code runs on Cloudflare Workers with read-only lessons published from home (see "Online version" below and [docs/CLOUDFLARE.md](docs/CLOUDFLARE.md)).

- Full specification: [docs/PROJECT_SPEC.md](docs/PROJECT_SPEC.md)
- Build plan & status: [docs/BUILD_PROMPTS.md](docs/BUILD_PROMPTS.md)
- Book drop folder rules: [resources/book/README.md](resources/book/README.md)
- Next.js 16 rules: @AGENTS.md — this is Next.js **16.4** with `cacheComponents`; read `node_modules/next/dist/docs/` before using a Next API.

## Stack (do not change without asking)
- Next.js 16 (App Router, `cacheComponents: true`) + React 19 + TypeScript (strict) + Tailwind CSS 4
- SQLite via Node's built-in **`node:sqlite`** (`data/app.db`) — no ORM, no native build step on Windows. Schema in `src/server/db.ts`, queries in `src/server/repo.ts`.
- Zod 4 for every content schema (`src/lib/schemas/`) — UI, DB layer and AI-output validation share them; prompt JSON Schemas come from `z.toJSONSchema`.
- CSS keyframe animations (no animation library), Web Speech API (en-US TTS + recognition), synthesized sound effects (Web Audio).
- pdfjs-dist + @napi-rs/canvas to render PDF pages.
- kokoro-js + @huggingface/transformers (Kokoro-82M, **fp32** on the CPU — ~3× faster than q8 on the family PC; q8 is the fallback/first-download model, `KOKORO_DTYPE=q8`) for the natural voice — used only by scripts, never imported by Next.js code.
- Long jobs (import, resources, voice) run as scripts via `runScript()` (`src/server/scripts.ts`) and stream JSON-line progress over SSE.
- Vitest (unit + pipeline with a fake CLI). Playwright e2e in the installed **Microsoft Edge** (`channel: "msedge"`, no browser download), production build, temp DB, fake CLI — `npm run e2e`.
- AI = server-side spawn of the local **Claude Code CLI** (`claude -p`), never from the browser.
- Online build: **@opennextjs/cloudflare** + **wrangler** (Cloudflare Workers, `wrangler.jsonc`, `open-next.config.ts`), **D1** for family data; `@breezystack/lamejs` (dev only) encodes the exported voice to MP3.

## Hard rules
1. **Books are the source of truth.** All lesson content is generated from what the book units actually teach (words, sentence patterns, phonics, topics). Don't invent curriculum that isn't in the imported books.
2. **Two content worlds, never mixed:** `source = "book"` (from imported textbooks) and `source = "inspiration"` (free topics the parent creates in AI Studio). Separate routes, sidebar sections and DB filters. Inspiration content never modifies book content.
3. **Age/level comes from the book analysis** (`src/lib/assessment.ts`, spec §3). Every generated item is calibrated to its book's `generationProfile`, and the child's age is matched against it (`childFit`).
4. **Adding a book makes its whole learning-resource set automatically** (`src/server/books/resources.ts`): import → units (auto-approved) → per unit, Claude writes grammar/reading/listening/speaking/quiz/lessonPlan/test and the offline builder makes vocabulary/games/worksheet (offline builder for everything if Claude fails) → items are **live** (`approved`) → natural voice pre-generated. The parent can edit (form editor, `src/features/parent/editor.tsx`, driven by the Zod schemas), hide or remake. Extra practice from the unit page and AI Studio packs stay **draft first**.
4c. **Lesson rules** (`src/lib/rules.ts`, page `/parent/rules`, setting `lessonRules`): every book lesson follows the family's rules. Four built-ins switch real behaviour and their wording is editable; parents can add their own (passed to Claude as written):
   - `book-only` — Claude items with word labels outside the book (unit + earlier units) are dropped by `enforceRules()` (`src/server/content.ts`) and made offline instead;
   - `book-pictures` — words show the **book's own picture**: the unit extraction returns `pic: {page, box}` per word, `/api/books/[bookId]/crop` cuts it from the rendered page (cached in `resources/.cache/<book>/crops/`), players use `<Pic>` (`src/components/Pic.tsx`) with the map from `picturesForItem()` (`src/server/pictures.ts`), emoji only as fallback. The parent can re-pick a picture on the unit page (`picker.tsx`);
   - `book-reading` — the Reading item's passage is the unit's own `readings` text (or its `sentences`) word for word (`bookTexts()`/`isFromBook()` in `src/lib/bookText.ts`);
   - `kid-clear` — prompt guidance only.
   The extraction also keeps the unit's printed `sentences`; examples, listening and speaking use them first.
4a. Books are added from the dashboard (**📤 Upload a PDF book** → `/api/books/upload` saves into `resources/book/` and the page starts the import) or by copying PDFs into the folder. The demo book/child is **not** created automatically — only with `npm run db:seed` or `SUNNY_DEMO=1` (the e2e suite sets it).
4b. **Children ↔ books & topics:** a child has `bookIds` (one or more books) and an `activeBookId`; the child's world shows only those books' ready lessons. **Inspiration topics are given per child** too (`topicIds`, ticked in Children → Edit): a Bonus island shows only for the children it was given to, and only when approved. Saving AI Studio output never gives it to anyone by itself.
4e. **Sticker album & trophies** (`src/lib/stickers.ts`): 14 themed pages × 8 stickers (land animals, sea, bugs, vehicles, robots — original SVG `RobotArt` —, boats, space, farm, birds, fruit, treats, music, sports, weather), one sticker per `STARS_PER_STICKER` (5) stars, earned in album order (the `stickers` table = one row per owned sticker, in order; `syncStickers()` in `db.ts` moves old codes into the album and adds stickers the stars already paid for). A full page wins its trophy (bronze/silver/gold by level); level = trophies. `recordAttempt` returns `newTrophies` for the celebration. Sticker names and page titles are speakables.
4f. **Speaking playback**: while the child speaks, the mic is also recorded (`MediaRecorder`) so they can press 👂 **Hear myself**; the recording is only a `blob:` URL in memory — dropped on Next and when leaving the activity, never saved or uploaded.
4d. **Answering = retry until right** (`src/features/players/quiz.tsx`): a wrong pick is shown as wrong (❌, red, `AnswerFeedback` "Oops! That's not right. Try again!" + the voice line `TRY_AGAIN`) and locked; "Next" appears only once the right answer is chosen; after `HINT_AFTER` (2) misses the right answer glows. Score/stars and `missed` count first-try answers. Every player with right/wrong answers follows this (quiz, test, grammar/reading practice, listening, every mini game — use `scoreRound()` from `gameKit.tsx`).
5. **Child mode has no AI access**, no free text chat, no external links. Parent mode is behind a local PIN (a child lock, not security).
6. **Validate all AI output with Zod.** `runForJson` retries once with the Zod errors; then show a friendly error. Never crash.
7. **Books stay private.** PDFs, rendered pages, picture crops and extracted data are gitignored and never uploaded or published; book pictures and reading texts are shown only inside this app, for the family that owns the book. **One exception, made on purpose by the parent:** the online export (`npm run online:export`) writes the *live* lessons, the word pictures cut from the book, the cover, the chosen topic pictures and the voice clips to `content/online/` + `public/online/`, which the parent commits to a **private** repository and publishes on their Cloudflare Worker (protected with Cloudflare Access — docs/CLOUDFLARE.md). Never export PDFs, page images, drafts, chats, attached files or children's data. The same goes for files attached in AI Studio (`data/studio/`) and topic pictures and style pictures (`data/topics/`). The only thing the app itself sends to the internet is, in the optional "web" picture mode, an AI Studio topic's picture search words (to Openverse) — never files, book content or names. (Style pictures go only to the local Claude Code, like any other chat attachment.)
7b. **AI Studio topic pictures** (`src/server/pictureJob.ts`, `pictureStyle.ts`, `pictureSearch.ts`, `topicPictures.ts`, `scripts/topic-pictures.ts`, setting `topicPictures` = **draw** (default) | web | off). After "Save as draft topic" (the POST carries the chat's `threadId`) the chat's attached pictures are copied to `data/topics/<topic>/style/ref-N.*` (`styleFromChat()`, ≤ 4; the parent adds/removes more on the topic page via `/api/topics/[id]/style`). The background job: (1) **style** — Claude opens the style pictures (Read, cwd = topic folder) and writes a style (`PictureStyle`: summary, palette, outline, fill, shapes, background, details) to `style/style.json`; without pictures it picks one that fits the topic; it is reused while the pictures' signature (`refsSignature`) is unchanged. Only the *look* is taken — never characters, logos or text. (2) **draw** — `claudePictureDraw` with the style text, `BATCH` words per call, `PARALLEL` calls at once (`RunOptions.parallel` skips the bridge's one-at-a-time queue; only inside this job's own process); SVG checked by `safeSvg` (shapes + soft filters, no text/images/scripts/outside references) → `ai.png`. (3) **check** — a numbered `review.jpg` of the drawings; Claude (`picture-review.md`) names the ones a 4-year-old wouldn't recognize or that don't match the style, with a fix; those are drawn once more (≤ `MAX_REDRAW`). In "web" mode Claude first plans each word and picks openly licensed **Openverse** pictures from numbered sheets (only search words leave the PC); the rest goes through steps 1–3. Saved in `inspiration_topics.pictures`; players get them through `picturesForItem()`. Without Claude nothing is guessed (emoji stay).
7c. **Mini games** (`src/lib/games.ts`, players in `src/features/players/games.tsx` + `minigames.tsx` + `gameKit.tsx`): 11 kinds on the same data (words + emoji/picture; `sort` also needs categories). **Every unit/topic gets two**, from `pickGames()`: topic theme match (regex per game) + less-used games first + not the games of the two units before (`earlierGames()`) + two different play families. Book units: in `buildQuickPack` (`opts.games` = history). AI Studio: the prompt lists the games (`gameCatalog()`) and the newest topics' games; `topUpGames()` adds games on save when a pack has fewer than two. `src/server/gameRefresh.ts` runs once (settings key `games_v2`) inside `migrate()`: units whose games are still the untouched automatic Memory/Balloon/Spelling get two picked games; topics with < 2 games get one more. Everything a game says comes from `GAME_SAY`/`GAME_LINES` and is listed by `gameSpeakables()`. Animations are CSS (`globals.css` "Mini games"); moving targets keep a visible base position and stop under `prefers-reduced-motion`. The editor lets the parent switch a game's kind.
7a. **AI Studio attachments** (spec §6.3): pictures, PDF, `.docx`, `.xlsx`/`.csv`, `.pptx`, text. Read without extra libraries — own ZIP + OOXML reader in `src/server/files/` (`zip.ts`, `office.ts`), pdfjs for PDFs, @napi-rs/canvas for pictures — in a separate process (`scripts/studio-file.ts`, started by `addStudioFile()` in `src/server/studioFiles.ts`). Claude gets the text inline (`filesPrompt()` in `jobs.ts`) and opens the pictures with **Read**, confined to the chat's folder (`--restricted`); the studio's Claude always runs with that folder as cwd so `--resume` keeps working. Unreadable files get a parent-friendly `FileProblem` message.
8. **Voice = American English** (`en-US`) everywhere. Default engine is the **natural Kokoro voice** (`af_heart`, offline neural TTS): `scripts/tts-worker.ts` runs it in its own process, `/api/tts` serves cached WAVs from `data/tts/`, model in `data/models/`. Browser Web Speech is only a fallback. Anything a player speaks must also be listed in `src/lib/speakables.ts` so it can be pre-generated.
8b. **Voice speed** (`src/server/tts/client.ts`, `warm.ts`): one worker makes one clip at a time; the server queue has priorities **now** (a tap / `<audio>` request) > **soon** (prefetch, header `x-tts-priority: soon`, same URL so the browser cache fills) > **idle** (background warm-up). The warm-up makes every approved lesson's missing clips after start-up and whenever lessons, topics, voice or speed change (pauses while a book import or "Prepare voices" runs). Players ask for texts **part by part** (`speechUnits()`): a passage starts after its first sentence; the next part is fetched while one plays. Buttons show ⏳ until the voice starts (`onStart`/`onDone` in `speak()`); after `NATURAL_WAIT_MS` the browser voice answers instead (the clip is still cached).
8a. **Pauses when reading** (`src/lib/speechPlan.ts`, shared by the engine, the browser voice and the word highlighting): `normalizeSpeech` keeps line breaks; a text is read in parts — one per sentence / line (a line going on in small letters is joined) — and joined with silences (`PAUSE`: sentence < line < paragraph, longer at slow speed; `src/server/tts/stitch.ts`). Dialogue labels ("A:", "Mai:") are not read, "____" becomes a short pause, emoji are dropped. A word or one plain sentence keeps its old cache key; texts read in parts include `PLAN_VERSION` in the key — **bump it whenever splitting/pauses change** so the cached audio is made again.
9. **Kid-friendly UI:** touch targets ≥ 48px, child-mode text ≥ 20px, bright palette (`src/app/globals.css` tokens), respect `prefers-reduced-motion`.
10. English UI; vocabulary may carry an optional Vietnamese meaning (`vi`) shown to the parent.

## Online version (Cloudflare Workers) — docs/CLOUDFLARE.md
- `ONLINE` (`src/lib/mode.ts`) = build flag `NEXT_PUBLIC_SUNNY_ONLINE=1`, set by `npm run cf:build`. Same code, two builds: every change must keep **both** working.
- **Home-only** (book import, AI Studio/Claude, voice engine, creating or changing lessons, rules, topic pictures, book pages): wrap the route handler in `localOnly()` (`src/server/api.ts` → 403 `HOME_ONLY`) and hide the UI with `<HomeOnly>` / `ONLINE` (`src/components/online.tsx`). New native or heavy packages: add them to `HOME_ONLY_PACKAGES` in `next.config.ts` (aliased to `src/server/homeOnlyStub.ts`).
- **Lessons online** are read-only, from `content/online/snapshot.json` (`src/server/snapshot.ts`); the lesson reads in `repo.ts` branch on `ONLINE`. **Family data** (settings, PIN, children, attempts, stickers) in routes that run online goes through `family()` (`src/server/family.ts`, async; home = SQLite repo, online = D1 `DB`). Don't call the sync family functions of `repo.ts` from such routes. The shared logic (`appSettingsFrom`, `childValues`, `statsFrom`, `stickerGain`…) lives in `repo.ts`.
- **Static files online**: `public/online/…` named by `src/lib/assetKeys.ts` — the same keys as the home caches (`ttsKey` = `data/tts` WAV name, `cropKey` = book crop name). `cropUrl`, `coverUrl`, `topicPictureUrl` and `naturalUrl` switch to them online. A new picture size or URL builder must be exported too (`CROP_SIZES`, `scripts/online-export.ts`). Anything spoken outside lessons goes in `appSpeakables()`.
- Online settings: the natural voice and speed are fixed to the exported ones (`onlineSettings()`); the parent only chooses natural/browser voice.
- **No `cacheComponents` online** (it hangs page rendering in workerd; `next.config.ts` turns it off). A new dynamic page needs `export const generateStaticParams = static…` from `src/server/onlinePages.ts` (undefined at home: Cache Components rejects an empty list), so it is prerendered online and served from static assets (`open-next.config.ts`). Reading `searchParams` on the server makes a page dynamic — read it in the client (`useSearchParams`, under `<Suspense>`).
- Runtime folders must not be traced into builds: `outputFileTracingExcludes` in `next.config.ts`, plus `/*turbopackIgnore: true*/` where Turbopack warns ("Dynamic filesystem access causes tracing of the whole project").
- Check the online build locally with `npm run cf:preview` (workerd + local D1 in `.wrangler/`). Plain `wrangler dev` skips filling the static page cache.

## Next.js 16 patterns used here
- Every API route is wrapped with `route()` from `src/server/api.ts`: it calls `await connection()` **outside** try/catch (so prerendering stops correctly), seeds the demo once, and uses `unstable_rethrow` in the catch.
- Pages with dynamic params: `<Suspense>{params.then(({ id }) => <ClientScreen id={id} />)}</Suspense>`.
- Client hooks that read runtime URL data (`usePathname`, …) must sit under a `<Suspense>` (see `src/app/parent/layout.tsx`).
- Data fetching is client-side via `useApi()` (`src/lib/client/api.ts`); long jobs stream Server-Sent Events (`sse()` / `streamSSE()`).
- React 19 lint forbids `setState` directly in effects — derive state, use `useSyncExternalStore` for storage (`useChildId`, `useParentUnlocked`).
- **Effects always use a block body** (`useEffect(() => { … })`). Never return an expression: current Edge/Chrome return a Promise from `scrollIntoView()`, and returning it from an effect crashed AI Studio ("i is not a function"). API smoke tests can't catch this — run `npm run e2e`.

## Windows notes
- Shell is PowerShell. The CLI is spawned with `shell: true`; prompts go via **stdin**, not argv. Env markers of an enclosing Claude Code session are stripped.
- Which Claude (`resolveCli()` in `src/server/claude/bridge.ts`): `CLAUDE_CLI_PATH` → `claude` on PATH → **the Claude Code bundled with the VS Code extension** (`~/.vscode/extensions/anthropic.claude-code-*/resources/native-binary/claude.exe`, newest). Same login as the VS Code extension. Check with `npm run claude:check`.
- Flags (verified against Claude Code 2.1.330 `--help`): `-p --output-format stream-json --verbose --include-partial-messages --tools <set> --allowedTools --disallowedTools --restricted --strict-mcp-config --resume --max-turns --add-dir --model`. Generation jobs run with `--tools ""` (no tools); book extraction with `--tools Read` and cwd = the book's pages folder; AI Studio with cwd = `data/studio/<threadId>/` and `--tools Read` only when the chat has attached files.
- Optional env: `CLAUDE_MODEL`, `CLAUDE_EXTRA_ARGS`, `CLAUDE_STREAM_PARTIAL=0`, `CLAUDE_RESTRICTED=0`.
- Book file names may contain spaces/Vietnamese characters — always use `path` APIs.

## Commands
- **`Start_English_Dashboard.bat`** — what the family double-clicks: checks Node, `npm install` on first run, `npm run build` when `src/`/`package.json`/`next.config.ts` is newer than `.next/BUILD_ID` or when `.next/required-server-files.json`'s `appDir` is not this folder (moved/renamed), then `next start` on **port 3210** and opens the browser (or only opens the browser if the app already runs). Keep it CRLF + UTF-8 without BOM. `SUNNY_NO_BROWSER=1` skips opening the browser (for testing).
- `npm run dev` — http://127.0.0.1:3000
- `npm run build` / `npm start`
- `npm test` — Vitest (uses `tests/fixtures/fake-claude.mjs`, no login needed)
- `npm run e2e` — build + Playwright in Edge (`tests/e2e/`): PIN setup, all screens, AI Studio chat→save and file attachments, child quiz, every mini game played to the end, wrong answer → try again, topics given per child, topic pictures + style box, hear-myself playback (fake mic + fake recogniser), sticker trophy. Uses a fake voice worker (`TTS_WORKER`) and no web (`OPENVERSE_URL` unreachable). Moving game targets are tapped with `dispatchEvent("click")` (they never stand still for `click()`); the parrot's tiles carry `data-seq` for the test.
- `npm run typecheck` / `npm run lint`
- `npm run claude:check` — which Claude Code is used + one tiny real call (`-- --no-call` to skip the call)
- `npm run book:scan` — list PDFs in `resources/book/` and their import status
- `npm run book:render` — only render PDF pages to PNG (no Claude)
- `npm run book:import -- <bookId|all> [--force] [--resources-only] [--no-resources] [--no-voice] [--no-claude]` — render + Claude extraction + assessment + learning resources + voice
- `npm run tts:prepare -- [all|<bookId>|<topicId>]` — pre-generate the natural voice for approved lessons
- `npm run db:seed [-- --force]` — demo book + sync `content/books/**` JSON into SQLite
- `npm run online:export` — write the online version's files (`content/online/snapshot.json`, `public/online/**`; also the **🌐 Online version** button in Settings at home). Then commit + push; Cloudflare Workers Builds runs `npm run cf:build` + `npx opennextjs-cloudflare deploy`.
- `npm run cf:build` — online build (OpenNext → `.open-next/`); deletes `.next/BUILD_ID` so the `.bat` rebuilds the home app · `npm run cf:preview` — build + run it locally on :8787 · `npm run cf:deploy` — build + deploy from this PC (needs `npx wrangler login`)
